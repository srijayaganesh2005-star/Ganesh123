# OVELOOP — free-tier deployment guide

This project is prepared for a Vercel React/Vite frontend, a Render Express API, and MongoDB Atlas. The ZIP intentionally excludes `.git`, all `node_modules`, built `client/dist`, and the original `server/.env`.

## Security before deployment

The original upload contained a real `server/.env` and a Git repository. Treat any credentials that were present in that file as exposed: rotate the MongoDB database password, JWT secret, admin password, and email/app password before deployment. This cleaned ZIP omits `.git` history, but rotating secrets is still necessary. Never commit your real `.env`.

## 1. Create MongoDB Atlas database

1. Create a free cluster at https://www.mongodb.com/cloud/atlas.
2. Create a database user with a strong unique password.
3. In Network Access, allow Render's outbound access. For a temporary student/demo setup, Atlas may require `0.0.0.0/0`; this allows connections from any IP, so use a strong database password and least-privilege database user. Restrict this further if you have a stable egress IP or a suitable paid plan.
4. Copy the Atlas connection string. Replace the username/password placeholders and select the intended database name. Keep it private.

## 2. Deploy API on Render

1. Upload this cleaned folder to a **new GitHub repository**. Do not include your original `.env` or old `.git` history. Keep the repo private while setting it up.
2. In Render, choose **New → Blueprint** and select the repository containing `render.yaml`, or create a **New → Web Service** manually.
3. If using the Blueprint, confirm the service settings: root directory `server`, build command `npm install`, start command `npm start`, health check `/api/health`, Free plan.
4. Set `MONGO_URI` to your Atlas connection string. Set `CLIENT_ORIGIN` to the exact Vercel URL after the frontend is deployed (no trailing slash). Add the rotated `ADMIN_EMAIL` and `ADMIN_PASSWORD`. Add `EMAIL_USER`, `EMAIL_PASS`, and `INTERNSHIP_EMAIL` only if email features are needed. `JWT_SECRET` is generated by the Blueprint; if creating a manual service, set a long random value yourself.
5. Deploy. Copy the resulting backend URL, e.g. `https://oveloop-api.onrender.com` (your actual URL will differ).

## 3. Deploy frontend on Vercel

1. In Vercel, import the same GitHub repository.
2. Set **Root Directory** to `client`; framework should be Vite; build command `npm run build`; output directory `dist`.
3. In Project Settings → Environment Variables, add `VITE_API_URL` with the exact Render backend URL, such as `https://oveloop-api.onrender.com` (no trailing slash). This variable is public because Vite embeds `VITE_*` values in browser assets; never store secrets there.
4. Deploy and copy your Vercel URL.
5. Return to Render and set `CLIENT_ORIGIN` to that exact Vercel URL, then redeploy the backend. If you use a Vercel custom domain, include that origin too, comma-separated.

## 4. Verify

- Open `https://YOUR-RENDER-URL/api/health`. It should return a JSON health status; `database` should be `connected`.
- Open the Vercel site and test registration, login, games, leaderboard, rewards, internships, and admin workflows.
- If requests fail, check the browser DevTools Network/Console and Render logs. Confirm `VITE_API_URL` is set and redeploy after changing it.

## Notes

- The frontend API calls now use `VITE_API_URL`. In local Vite development, the fallback remains `http://localhost:5000`; in production, set `VITE_API_URL` in Vercel.
- Render free web services can spin down after inactivity, so the first request after a quiet period may be slow. Free tiers are suitable for demos/testing, not production guarantees.
- Email delivery may not work on Render's free tier if the provider requires blocked outbound SMTP ports. Consider a transactional email API if needed.
- This configuration does not prove every app feature works against a production database; run the feature checks above before sharing the URL.
